# Постоянная установка и патчи

Camera Deck Client использует один канал camera-deck-client-v* в публичном репозитории Camera-Deck. Windows и Android имеют общий номер версии, протокол и подписанный манифест. Не нужно создавать новый профиль и заново сопрягать устройства для каждого релиза.

## Установка

1. На Windows запустите CameraDeck-Setup.exe. Программа устанавливается в LOCALAPPDATA/CameraDeck/Client/CameraDeck.exe, настройки остаются в LOCALAPPDATA/CameraDeck. Один ярлык в меню Пуск, права администратора не нужны.
2. На Android установите CameraDeck-Android.apk поверх Slate 0.10.0 с совпадающим сертификатом. Не удаляйте приложение: это удаляет приватные исходники. Преемственность подписи старых Aurora 0.9 не подтверждена.
3. Один раз разрешите установку обновлений из Camera Deck в системных настройках Android. ОС может дополнительно запросить подтверждение. Полностью бесшумная установка зависит от версии и политики Android.

## Установка патчей

Открытые клиенты проверяют GitHub раз в 15 минут; Android без открытого приложения использует JobScheduler: 6 часов, сеть без тарификации, реальное время выбирает ОС. Windows передаёт подписанный APK обновлённому телефону по существующему защищённому подключению, в том числе через USB без LAN. Первая миграция со Slate 0.10 выполняется вручную: старый канал не доверяет новому ключу манифестов.

Windows ждёт завершения записи/восстановления файлов и 30 секунд без ввода. Android ждёт завершения фото/видео, публикации галереи, обработки портретов и простоя камеры. При постоянно включённой камере патч остаётся готовым до её остановки. После обновления камеру может понадобиться включить вручную.

Переподключение USB восстанавливает только ранее сохранённые доверенные устройства с тем же отпечатком TLS; проверка сертификата сохраняется.

## Защита и восстановление

Манифест подписан RSA/SHA-256, содержит размер и SHA-256 каждого пакета. APK дополнительно проверяется по имени пакета, коду версии и текущему сертификату. Проверки повторяются перед установкой. Публичные ключи зафиксированы в исходниках; закрытые ключи хранятся вне репозитория в защищённом хранилище и секретах CI. Потеря ключа блокирует выпуск несовместимой версии.

Windows сохраняет предыдущий EXE. Если новый клиент не подтвердил запуск интерфейса за 45 секунд, установщик возвращает предыдущую программу и блокирует автоматический повтор того же неудачного патча. Это контроль запуска, а не гарантия отсутствия ошибок камеры. Android использует системную атомарную установку; собственного отката после успешной установки APK нет.

Дочерний установщик получает независимое окружение и корректные потоки ввода/вывода. Для Windows PowerShell удаляется унаследованный PSModulePath: при запуске через Python пути PowerShell 7 могут нарушить загрузку системных команд. Это поведение описано в [документации Microsoft](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_psmodulepath).

Исходники и файлы галереи не удаляются обновлением. Публикация в галерею требует дополнительного свободного места; при ошибке сохраняется приватный исходник. Экспериментальное размытие создаёт отдельную копию.

## Выпуск

Workflow client-release.yml собирает и проверяет обе платформы, сверяет идентичность APK, подписывает манифест и публикует предварительный релиз. Публикация из незафиксированных исходников или с изменённым сертификатом блокируется. Уже опубликованные пакеты не перезаписываются.
