# Slate 0.10.0: USB, звуковой тракт и компактный интерфейс

Исходный кандидат, versionCode 15. Новый APK не установлен на пользовательский телефон: на этом ПК отсутствуют исходные Aurora APK/update signing identities. Debug APK из CI не является обновлением установленной Slate. Идентичность подписи не подменяется.

## Подключение кабелем

В Windows: **Устройства → Подключиться по USB** или кнопка **USB · кабель**. Нужен USB-кабель с передачей данных. На телефоне включите параметры разработчика/USB-отладку и разрешите этот компьютер штатным запросом Android; затем включите камеру в Camera Deck. Wi-Fi, USB-модем и общая локальная сеть для этого способа не нужны.

Windows-сборки включают adb.exe, AdbWinApi.dll, AdbWinUsbApi.dll и NOTICE.txt. При запуске из исходников нужны Android Platform Tools; путь можно задать через CAMERA_DECK_ADB или ANDROID_SDK_ROOT/ANDROID_HOME. На некоторых ПК потребуется драйвер производителя для Android ADB.

Каждому телефону выделяется собственный локальный порт `127.0.0.1`; сетевые ADB-адреса и эмуляторы не выдаются за кабель. При повторном подключении проверяется наличие туннеля, исчезнувший создаётся заново. Полный TLS fingerprint проверяется до отправки PIN/token. Первое сопряжение — с PIN; сохранённое доверие используется только при совпадении сертификата. Параллельный второй сеанс того же телефона через Wi-Fi/USB не создаётся. При закрытии Windows убираются только туннели этого экземпляра приложения; чужие forward и ADB server не останавливаются.

## Звук

Windows: рабочее пространство **Камера → Источник / выход звука**. Выбираются вход, который Android сообщает на телефоне, и отдельный выход ноутбука. Доступны автоматический вход и видимые Android встроенные/проводные/USB/Bluetooth-входы. Android может не исполнить предпочтение маршрутизации: показываются фактический вход и предупреждение о несовпадении. Поддержка конкретной гарнитуры не обещается до аппаратного теста.

На телефоне выбор входа находится в **Ещё → Вход звука на телефоне**. Смена микрофона во время записи запрещена, чтобы не перестраивать AudioRecord в середине дубля. При отключении выбранного микрофона отображается изменение маршрута/ошибка; действуют прежние механизмы предупреждения о пропусках аудио.

Выход Windows выбирается независимо от микрофона и звуковой дорожки видео. Есть системный выход и конкретные колонки/наушники; громкость меняет только прослушивание. Если выход исчезает, показывается ошибка вместо незаметного переключения на другой. PCM телефона преобразуется в поддерживаемый формат выхода, когда устройству не подходит 48 кГц/mono/16 bit. Очередь остаётся ограниченной; при смене выхода старый звук сбрасывается.

## Экран и интерфейс

**Не гасить экран при записи** включено по умолчанию, выключается в меню «Ещё». Удержание относится к открытой Activity во время REC; после остановки/ухода в фон оно снимается. Пользователь может вручную выключить экран; системные настройки тайм-аута/зарядки не меняются. Работа записи в фоне остаётся отдельной функцией.

Чёрные нейтральные панели, компактные жёлтые настройки, меньшая нижняя панель Android. Убрано снимание/размытие окна при открытии диалогов Windows. Android повторно использует оформление кнопок; локальный предпросмотр и состояние проверяются чаще, команды показывают отклик сразу. Windows запрашивает состояние сразу после команды вместо ожидания следующего обычного опроса. Улучшение времени реакции пока не измерено на новом APK телефона.

## Проверка и ограничения

- 103 Python-теста: TLS, USB-порты/повторное подключение/очистка, отказ вывода, преобразование mono→stereo, прежние тесты записи и UI.
- Android debug-кандидат собран; 29 JVM-тестов и Lint пройдены. Это не тест реальных AudioRecord/MediaCodec/экрана.
- Windows onefile и portable собраны с ADB; оба EXE прошли `--self-test` (0.10.0, rendered=true, hardwareTested=false). Встроенный portable ADB запускается и сообщает версию. Код main.py в обоих EXE сравнён с текущим исходником. Исходные настройки пользователя изолированы от self-test.
- На подключённом S22 Ultra проверены обнаружение ADB и создание/удаление собственного USB-forward. Это не проверка записи через новый APK.
- Снимки в `screenshots/slate-usb-audio/` — работающий Windows-интерфейс с явно помеченными TLS-симуляторами. Это не реальные камеры.
- Аппаратные входы/выходы, удержание экрана и полный USB capture на версии 0.10.0 ещё требуют установки APK с исходной подписью. Результаты съёмки 0.9.0 нельзя переносить на этот кандидат.
- Подтверждённый ранее дефект 8/10 fps→около 15 fps остаётся открытым. Изменение интерфейса и USB его не исправляют.

Основание для реализации маршрута: [Android AudioRecord](https://developer.android.com/reference/android/media/AudioRecord#setPreferredDevice(android.media.AudioDeviceInfo)), удержания экрана: [Keep the screen on](https://developer.android.com/develop/background-work/background-tasks/awake/screen-on).
